## 一、OSM 作为变化标签的可行性分析

### 1.1 OSM 数据特性

OpenStreetMap (OSM) 是众包地理信息平台，核心数据包括：
- **建筑轮廓** (building=yes, building:*) — 部分地区较完整
- **道路网络** (highway=*) — 全球最完整
- **POI点** (amenity=*, shop=*) — 丰富
- **土地利用** (landuse=*) — **耕地标签极少**
- **完整历史记录** — 每个要素有 changeset、创建/修改/删除时间戳

### 1.2 OSM 用于变化检测的研究现状

已有研究尝试用OSM辅助变化检测，但方向是**反向**的：

| 研究方向 | 核心发现 | 对我们的启示 |
|---------|---------|------------|
| **IBM Research (2020)** | 用遥感影像检测OSM数据是否需要更新 | OSM本身不够准，需要遥感来修正 |
| **OpenEarthMap (2023)** | OSM + 光学影像的多模态变化检测 | OSM作为辅助输入，不是标签 |
| **Albrecht et al. (2020)** | fw-CycleGAN生成OSM更新热力图 | OSM变化 ≠ 真实地物变化 |
| **OSM质量评估 (2023)** | OSM数据质量不均匀， completeness因区域差异大 | 北京城市区域相对好，但农村地区差 |

### 1.3 OSM 作为季度变化标签的致命问题

#### 问题1: 时间分辨率完全不够（🔴 致命）

```
OSM的"时间" = 志愿者编辑时间 ≠ 地物实际变化时间

举例:
  真实变化: 2025年3月某建筑建成
  OSM编辑: 可能2025年8月才有人录入
  延迟: 数月甚至数年

季度变化检测要求: 11天/季度周期
OSM实际更新频率: 城市热点区域数月一次，偏远区域数年一次
```

**研究证实**: OSM completeness的饱和速度可作为质量指标，但即使"接近饱和"的区域，也无法保证季度级更新。

#### 问题2: 耕地标签几乎不存在（🔴 致命）

```
OSM标签体系:
  ✅ 建筑 (building=*) — 较丰富
  ✅ 道路 (highway=*) — 非常完整
  ⚠️ 水体 (water=*) — 部分有
  ❌ 耕地/农田 (landuse=farmland) — 极其稀少

原因: OSM志愿者主要关注"导航相关"地物（道路、建筑、POI）
      农田缺乏导航价值，极少被标注
```

任总的核心需求是**耕地变化检测**，OSM在这方面几乎无法提供任何标签。

#### 问题3: 几何精度不足（🟡 严重）

```
OSM建筑轮廓的配准误差: 平均约5米

研究发现 (ohsome2label, 2022):
  - 5米配准误差 + 30% completeness → recall仅17.43%
  - 需要100% completeness + 零配准误差才能保证准确率

Sentinel-1/2分辨率: 10-20米
OSM误差5米 = 占半个像元，对变化检测影响显著
```

#### 问题4: 中国区域覆盖不均（🟡 严重）

```
OSM数据质量分布:
  欧洲/北美: ⭐⭐⭐⭐⭐ 非常完整
  中国城市: ⭐⭐⭐ 建筑、道路较完整
  中国农村: ⭐⭐ 稀疏
  中国农田区域: ⭐ 几乎空白

海淀区虽然是城市区域，但关注的耕地位于北部四镇（上庄/西北旺/温泉/苏家坨），
属于城乡结合部，OSM覆盖度中等偏低。
```

### 1.4 OSM 的可用场景（有限）

| 场景 | 可用性 | 说明 |
|------|--------|------|
| **建筑变化初筛** | 🟡 可用 | 城市区域建筑轮廓可辅助定位变化热点 |
| **道路网络变化** | 🟡 可用 | 新修道路可在OSM中较快反映 |
| **耕地变化** | ❌ 不可用 | 几乎无标签 |
| **季度级检测** | ❌ 不可用 | 时间分辨率不够 |
| **年度级建筑变化** | ✅ 可用 | 可作为弱标签或辅助验证 |

## 二、精准地物变化标签来源全景

### 2.1 全球开源数据集

#### A. Microsoft TEMPO — 全球首份季度建筑变化数据（⭐⭐⭐⭐⭐ 强烈推荐）

**基本信息**:
- 发布机构: Microsoft AI for Good Research Lab
- 发布时间: **2025年11月**（非常新）
- 时间范围: **Q1 2018 ~ Q2 2025，季度更新**
- 空间分辨率: **37.6米/像素**
- 覆盖范围: **全球**
- 数据内容: 建筑密度 + 建筑高度
- 数据源: PlanetScope basemap + Overture Maps先验

**关键价值**:
```
✅ 真正的"季度"时间分辨率（第一个此类全球数据集）
✅ 可直接用于验证建筑/建成区变化
✅ F1 score 85-88%，时间一致性0.96（5年趋势一致性）
✅ 免费提供，GitHub可下载
```

**局限性**:
```
⚠️ 37.6米分辨率较粗（约等于Sentinel-2的4个像元）
⚠️ 只覆盖"建筑"，不覆盖耕地、林地等其他地物
⚠️ 建筑密度是连续值（0-1），需阈值分割才能做二值变化
```

**获取方式**:
- GitHub: https://github.com/microsoft/buildings
- Azure Blob Storage上的COG格式GeoTIFF

**对我们的价值**:
- 海淀区建筑变化可用TEMPO做**独立验证**
- 虽然37.6m分辨率无法精确到单栋建筑，但可以验证"区域级"变化趋势
- 2025年Q1-Q2的数据正好覆盖我们的时间窗口

---

#### B. Google Open Buildings 2.5D Temporal — 年度建筑变化（⭐⭐⭐⭐）

**基本信息**:
- 发布机构: Google Research Africa
- 时间范围: **2016-2023，年度**
- 空间分辨率: **0.5米（建筑轮廓级）**
- 覆盖范围: 非洲、南亚、东南亚、南美、加勒比
- **中国不在覆盖范围内** ❌

**关键价值**:
```
✅ 年度建筑存在/计数/高度
✅ 教师-学生模型生成，MAE仅1.5米
✅ 可检测建筑新增、拆除、高度变化
```

**局限性**:
```
❌ 中国区域不可用
⚠️ 年度分辨率，不够季度级
```

---

#### C. Microsoft Building Footprints — 全球建筑轮廓（⭐⭐⭐）

**基本信息**:
- 时间范围: 2014-2024（持续更新）
- 空间分辨率: **0.3-0.6米**
- 覆盖范围: 全球（但**中国区域不可用**）
- 已检测: 14亿栋建筑

**局限性**:
```
❌ 中国不可用
⚠️ 有编辑时间戳，但不提供完整的时序档案
⚠️ 更新是"增量式"而非"定期重采"
```

---

#### D. Overture Maps — 合作地图数据（⭐⭐⭐）

**基本信息**:
- 发布机构: 微软+Esri+Google+Meta合作
- 数据内容: 建筑、道路、POI、行政区划
- 时间: 主要是静态快照

**局限性**:
```
⚠️ 目前主要是2023年左右的快照
⚠️ 时序变化信息不足
⚠️ 中国区域覆盖有限
```

### 2.2 中国区域专用数据集

#### E. 吉林一号耕地变化检测数据集 — 最相关（⭐⭐⭐⭐⭐ 强烈推荐）

**基本信息**:
- 发布机构: 长光卫星（吉林一号网）
- 数据量: **8000余组**（训练6000 + 测试2000）
- 分辨率: **优于0.75米**
- 图像尺寸: 256×256像素
- 格式: RGB三通道TIF + 单通道PNG标签

**变化类别（8类精细标签）**:
```
1 — 耕地变为道路
2 — 耕地变为林草
3 — 耕地变为建筑
4 — 耕地变为其他
5 — 道路变为耕地
6 — 林草变为耕地
7 — 建筑变为耕地
8 — 其他变为耕地
0 — 非耕地变化区域
```

**关键价值**:
```
✅ 专门面向"耕地变化"，与任总需求完全匹配
✅ 8类变化方向标签（不仅二值变化，还有变化类型）
✅ 高分辨率（<0.75m），精细到田块级别
✅ 中国数据，免费下载（需教育用户注册）
```

**获取方式**:
1. 在吉林一号网(https://www.jl1mall.com/)注册教育用户
2. 进入【遥感商城】【资源中心】【大赛数据集】
3. 下载"耕地变化检测数据集"

**局限性**:
```
⚠️ 数据区域未知（可能不在海淀区）
⚠️ 只有双时相对，不是连续时序
⚠️ 分辨率0.75m，与我们的10-20m Sentinel数据不匹配
⚠️ 不能直接作为"标签"用，但可用于：
     - 验证模型对耕地变化的检测能力
     - 作为预训练数据增强模型泛化性
```

**使用建议**:
```
不能直接作为海淀区标签，因为：
  1. 地理位置不匹配
  2. 分辨率差距大（0.75m vs 10-20m）

但有重要参考价值：
  1. 可用来预训练或微调变化检测head
  2. 验证模型对"耕地→建筑"等特定变化的检测能力
  3. 了解耕地变化检测的标注标准和难点
```

## 三、季度变化标签获取策略建议

### 3.1 结论: 不存在完美的"季度变化标签"

**当前现状**:
```
季度变化检测（11天/季度周期）是一个极其前沿的需求，
相应的"季度级变化标签"在全球范围内几乎不存在。

原因:
  1. 人工标注成本极高（每季度标注一次 = 4倍年度成本）
  2. 多数变化在季度尺度上是渐进、不明显的
  3. 学术界的变化检测数据集主要是"双时相"而非"连续时序"
```

### 3.2 推荐的分层标签策略

```
┌─────────────────────────────────────────────────────────────┐
│  第一层: 政府权威数据（年度精度）                              │
│  ├── 三调数据库（2019基准）                                   │
│  ├── 年度国土变更调查（2024-2025变化图斑）                     │
│  └── 永久基本农田红线（空间范围）                              │
│  用途: 年度变化验证 + 耕地监测范围定义                         │
├─────────────────────────────────────────────────────────────┤
│  第二层: 开源遥感产品（季度-年度精度）                         │
│  ├── Microsoft TEMPO（季度建筑密度，37.6m）                   │
│  ├── ESA WorldCover（年度10m土地覆盖）                        │
│  └── CLCD（年度30m中国土地覆盖）                              │
│  用途: 季度建筑变化趋势验证 + 年度地类变化参考                 │
├─────────────────────────────────────────────────────────────┤
│  第三层: 学术数据集（模型能力验证）                            │
│  ├── OSCD（Sentinel-2建筑变化，10m）                          │
│  ├── 吉林一号耕地变化（<0.75m，8类变化）                      │
│  └── LEVIR-CD / WHU-CD（高分辨率建筑变化）                    │
│  用途: 验证模型检测能力 + 预训练数据                           │
├─────────────────────────────────────────────────────────────┤
│  第四层: 自生成伪标签（无标签场景）                            │
│  ├── 变化向量分析(CVA)自动生成                                 │
│  ├── Mean Teacher半监督伪标签                                  │
│  └── 阈值分割 + 人工抽检确认                                   │
│  用途: 季度高频检测的日常运行                                  │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 对海淀区11天检测的具体建议

```
Step 1: 定义"变化"
  - 季度尺度的"变化"与年度不同
  - 耕地季度变化: 翻耕、播种、灌溉、收割（季节性变化 ≠ 地类变化）
  - 真正的"变化": 耕地→建筑、耕地→道路（非农化）
  - 建议: SAR检测"地表扰动" + 光学验证"地类变化"

Step 2: 标签获取路径
  路径A（年度验证）:
    - 2024年度变更调查图斑 vs 2025年度变更调查图斑
    - 直接对比 → 年度变化标签
    - 将年度变化分配到各个季度（近似）

  路径B（季度验证）:
    - Microsoft TEMPO季度建筑密度
    - 检测"建筑密度显著增加"的区域
    - 与SAR检测到的"地表扰动"区域重叠 → 高置信度变化

  路径C（无标签运行）:
    - 用CVA / 统计阈值生成伪变化标签
    - 人工抽检10-20个典型区域确认
    - 累积确认样本 → 逐步构建季度标签库

Step 3: 精度评估策略
  - 不需要"像素级完美标签"
  - 采用"区域级"评估: 检测到的变化区域是否与年度变更调查一致
  - 关注: 变化面积比例、变化热点位置、变化趋势方向
```

## 四、OSM 使用建议（如有需要）

如果仍希望使用OSM作为辅助输入:

```
适用场景:
  1. 城市区域建筑/道路变化初筛
  2. 验证"建成区扩张"方向
  3. 作为decoder的额外输入特征（非标签）

获取方式:
  - Overpass API: 按区域、按时间范围查询OSM要素
  - ohsome API: 获取OSM历史数据和时间序列统计
  - Geofabrik: 下载中国区域OSM数据dump

使用方法:
  - 提取building=yes的多边形 → 栅格化 → 作为先验输入
  - 对比不同时期的OSM建筑覆盖 → 识别"可能变化"区域
  - 注意: 只能作为"弱标签"或"辅助特征"，不能作为ground truth
```

## 五、调研总结

| 问题 | 答案 |
|------|------|
| **OSM能提取季度变化标签吗？** | **不能**。时间分辨率不够，耕地标签几乎不存在，中国城乡结合部覆盖差 |
| **有没有现成的季度变化标签？** | **全球几乎没有**。Microsoft TEMPO是唯一季度建筑数据，但37.6m分辨率且只覆盖建筑 |
| **最接近的可用数据集？** | **吉林一号耕地变化检测**（8类精细变化标签，<0.75m），但区域不匹配、分辨率差距大 |
| **最现实的标签方案？** | **分层策略**: 政府年度变更调查做基准验证 + TEMPO季度趋势参考 + 半监督/无监督日常运行 |
| **海淀区具体怎么做？** | 1. 申请年度变更调查图斑做年度验证<br>2. TEMPO验证建筑变化趋势<br>3. 无监督CVA + 人工抽检做季度检测<br>4. 累积样本逐步构建季度标签库 |
