## 二、待回答问题详细解答

### Q1: 生成的嵌入到底有没有用？怎么评估？

**回答: 有用，但必须通过下游任务验证，不能只看训练loss。**

#### 评估方法体系（四层）:

| 层级 | 方法 | 说明 | 当前项目支持情况 |
|------|------|------|----------------|
| **L1: 变化检测AUC** | 用before/after embedding计算cosine distance，与人工标注对比计算ROC-AUC | 最直接的业务指标 | ✅ 已有validate_v2.py等脚本 |
| **L2: KNN分类准确率** | 用embedding做k近邻居分类，测试其线性可分性 | 验证特征空间质量 | ✅ 配置中有knn_k参数 |
| **L3: 线性探测(Linear Probing)** | 冻结encoder，只训练线性分类头，测试特征表达能力 | 衡量embedding是否包含足够语义 | ⚠️ 需补充脚本 |
| **L4: 可视化分析** | t-SNE/UMAP降维可视化，观察同类样本是否聚集 | 直观展示embedding质量 | ⚠️ 需补充脚本 |

#### 关键评估指标对照表:

| 指标 | 正常范围 | 业务含义 |
|------|---------|---------|
| 变化检测AUC | > 0.7及格, > 0.8良好, > 0.85优秀 | 模型能否区分变化/未变化 |
| raw_unif | -4.0 ~ -1.0 | embedding是否坍缩 |
| recon | < 0.3 | 重建质量，验证encoder保留了足够信息 |
| 时间对比loss | 有效下降 | embedding是否时间敏感 |

> **给任总的汇报建议**: 准备一份"Embedding能力报告"，包含AUC曲线、可视化聚类图、时间敏感性热力图，用图形说话。

### Q2: 11天高频检测，标签数据跟不上？怎么解决？教室学生模型？

**回答: 这是核心痛点，需要从"全监督"转向"半监督/自监督"策略。**

#### 11天周期的问题:
- Sentinel-1重访周期约 **12天**（双星可缩短至 **6天**）
- 11天高频意味着 **一年约33对** 变化检测样本
- 人工标注完全跟不上这个频率

#### 解决方案矩阵:

| 方案 | 原理 | 适用场景 | 标签依赖度 |
|------|------|---------|----------|
| **① 自监督预训练+微调** | 先用大量无标签数据预训练（当前AEF方案），再用少量标签微调 | 通用场景 | 极低 |
| **② 变化向量分析(CVA)** | 直接比较双时相图像的向量差异，无需标签 | 快速初筛 | 零 |
| **③ Mean Teacher半监督** | 教师模型生成伪标签，学生模型学习，EMA更新教师 | 有少量标签时 | 低 |
| **④ 阈值自动提取** | 基于统计阈值自动分割变化区域，人工确认 | 特定地物 | 低 |
| **⑤ 主动学习** | 模型选择"最不确定"的样本请求人工标注 | 持续迭代 | 中等 |

#### "教师-学生模型"详解:

**Mean Teacher框架** 是半监督变化检测的SOTA方案:

```
有标签数据 ──→ 学生模型 ──→ 与真实标签算loss
                  ↑
无标签数据 ──→ 教师模型 ──→ 生成伪标签
                  ↑
         EMA更新(θ_teacher = α·θ_teacher + (1-α)·θ_student)
```

**适用性评估**:
- ✅ 适合我们的场景：有少量标注（105个光学标注），大量无标注SAR数据
- ✅ 与当前AEF架构兼容：encoder部分可以直接作为教师/学生的主干
- ⚠️ 需要新增：伪标签生成逻辑、EMA更新、一致性loss

> **建议**: 当前V6/V6.5 trainer基础上，新增一个`DDPv7SemiSupervisedTrainer`，集成Mean Teacher。

### Q3: SAR作为主要源会不会有问题？

**回答: SAR做主数据源可行，但必须解决三大问题。**

#### SAR的优势（为什么适合做主源）:
| 优势 | 说明 |
|------|------|
| 全天候 | 不受云雨影响，11天稳定获取 |
| 穿透性 | 对植被结构、地表粗糙度敏感 |
| 重访快 | Sentinel-1A/B双星，实际重访可缩短至6天 |
| 耕地敏感 | 对翻耕、灌溉、收割等地表扰动敏感 |

#### SAR的已知问题及解决方案:

| 问题 | 影响 | 解决方案 |
|------|------|---------|
| **相干斑噪声** | 图像颗粒感强，伪变化多 | 多视处理、精致Lee滤波、时序滤波 |
| **几何偏移** | 同一地物在不同时相图像上位置偏差 | 高精度配准（基于轨道参数+互相关） |
| **辐射校准** | 不同时间获取的后向散射值不直接可比 | 辐射定标+相对归一化 |
| **侧视畸变** | 山地地区阴影、叠掩 | 雅江场景需DEM辅助几何校正 |
| **语义模糊** | SAR难以区分某些地物（如水 vs 光滑路面） | 光学数据辅助验证 |

#### 雅江场景特殊注意:
- 雅江地形复杂，SAR侧视会造成 **阴影、透视收缩、叠掩**
- 冰川区域：SAR对冰川表面粗糙度敏感，但需区分 **冰川运动** vs **冰川消融**
- 疑似滑坡：SAR可以检测地表形变（InSAR），但11天时间基线太短，需累积多期

> **建议**: SAR做主源 + 光学做辅助验证/确认。变化检测用SAR，变化类型识别用光学。

### Q4: 海淀区的标签有哪些？能不能提取好的出来，高细腻度的？

**回答: 海淀区有较多公开数据可用，但高细腻度标签需要整合多个来源。**

#### 可用数据源:

| 数据源 | 分辨率 | 类别数 | 获取方式 | 适用性 |
|--------|--------|--------|---------|--------|
| **ESA WorldCover** | 10m | 11类 | 公开下载 | ⭐⭐⭐ 全球产品，局部精度一般 |
| **GlobeLand30** | 30m | 10类 | 公开下载 | ⭐⭐ 分辨率低，耕地边界模糊 |
| **FROM-GLC (清华)** | 30m | 10类 | 公开下载 | ⭐⭐ 更新较慢 |
| **CLCD (武大)** | 30m | 9类 | 公开下载 | ⭐⭐⭐ 年度更新 |
| **全国国土调查数据** | 亚米级 | 数十类 | 需对接 | ⭐⭐⭐⭐⭐ 最精细，但需协调 |
| **已有学术论文数据** |  varies | varies | 联系作者 | ⭐⭐⭐ 可能有现成的分类结果 |
| **Sentinel-2时序自分类** | 10m | 自定义 | 自处理 | ⭐⭐⭐ 可用聚类生成伪标签 |

#### 海淀区已有研究参考:
- 已有论文使用Sentinel-2对海淀区进行2018-2021土地利用监测
- 分类体系：建设用地、林地、耕地、水体、裸地等
- 耕地变化：海淀区耕地面积1986-2010年间减少45.7%，主要转为建设用地

#### 高细腻度标签获取策略:

```
第一步: 获取现有公开产品 (WorldCover/CLCD) 作为粗标签
           ↓
第二步: 用高分辨率影像 (Planet/高分) 局部精化
           ↓
第三步: 结合海淀区国土调查数据 (如可对接) 获取精细边界
           ↓
第四步: 对耕地等关注类别，人工标注样本 patches
           ↓
第五步: 用半监督方法 (Mean Teacher) 扩展标签到全区域
```

> **建议**: 先以WorldCover为起点，用变化检测筛选出"可能变化"区域，再人工精标这些区域。

### Q5: 遥感最重要的是能看到哪里发生了变化，可以快速展示变化

**回答: 这是产品化的核心，需要"检测+可视化+交互"三位一体的方案。**

#### 快速展示的技术路径:

| 环节 | 技术方案 | 时间成本 |
|------|---------|---------|
| **数据获取** | Sentinel-1实时流 / 商业SAR数据 | 11天周期 |
| **预处理** | 自动配准、去噪、辐射校正 | 数小时 |
| **变化检测** | 预训练AEF模型提取embedding → cosine distance → 阈值分割 | 分钟级/场景 |
| **结果呈现** | Web地图 (Leaflet/Mapbox) + 变化热力图 + 时间轴 | 实时 |
| **交互查询** | 点击地块 → 显示时间序列变化曲线 + 前后对比 | 实时 |

#### 现场演示的技术准备（雅江场景）:

```
预计算: 雅江区域历史embedding全部提取完毕（离线完成）
           ↓
现场演示: 客户指一块地 → 实时查询该区域的时间序列embedding
           ↓
展示内容:
  - 时间轴：该点/区域各时期的变化分数
  - 前后对比：双时相影像并列 + 变化掩码叠加
  - 变化类型：草地退化？冰川退缩？疑似滑坡？
```

> **给任总的建议**: 当前已有`demo/app.py` Gradio可视化，需要升级为支持时间轴交互的Web应用。

### Q6: 生成好的embedding的条件到底是什么？

**回答: 好embedding = 不坍缩 + 时间敏感 + 重建好 + 方差健康。**

#### 训练成功的四象限判定:

| 条件 | 监控指标 | 合格线 | 不合格表现 |
|------|---------|--------|----------|
| **① 不坍缩** | raw_unif | -4.0 ~ -1.0 | > -0.5 表示embedding坍缩到一个小区域 |
| **② 时间敏感** | temporal contrastive loss | 持续下降 | 不下降表示模型无法区分不同时间 |
| **③ 重建质量好** | recon loss | < 0.3 | > 0.5 表示encoder丢失太多信息 |
| **④ 方差健康** | var_reg | 接近0 | > 0.5 表示方差坍缩，特征维度退化 |

#### 好embedding的业务验证:

| 验证方法 | 通过标准 |
|---------|---------|
| 变化检测AUC | > 0.7 |
| t-SNE可视化 | 同类地物聚集，不同类分离 |
| 时间一致性 | 相邻时间窗口的embedding相似度高 |
| 跨源一致性 | 同一地点SAR和光学embedding在公共空间接近 |

## 四、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| Embedding AUC达不到0.7 | 无法证明技术价值 | 立即检查raw_unif，必要时调整loss weights重启训练 |
| SAR偏移过大导致伪变化 | 11天检测虚警率高 | 先做配准精度评估，不达标则不发布该指标 |
| 海淀区标签获取困难 | 无法监督验证 | 先用无监督CVA做基线，同步推进标签对接 |
| 雅江现场演示失败 | 客户信任度下降 | 预计算所有可能查询的embedding，准备离线backup |
| 半监督训练不稳定 | Mean Teacher引入噪声 | 从小比例伪标签开始，逐步增加 |
