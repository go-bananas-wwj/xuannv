## 一、我们在做什么？

### 1.1 项目目标

我们正在训练一个**遥感图像的AI Embedding模型**。简单说：

> 给模型输入一张遥感卫星图（比如 Sentinel-2），模型输出一个"特征向量"（128维数字）。
> 我们希望：**不同时间、不同地点的图像，输出的向量是不一样的**——这样下游任务（比如变化检测、地物分类）才能区分它们。

### 1.2 核心难点：Embedding坍缩

训练这类模型时，最容易出现的问题叫做**"坍缩"（Collapse）**：

> 模型发现"偷懒"的捷径——不管输入什么图像，都输出几乎一样的向量。
> 这样重建损失很低（模型学"会"了），但embedding完全没区分度，下游任务无法使用。

**类比**：就像学生考试作弊，把选择题全选C，得分可能不低，但完全没学到知识。

### 1.3 我们的武器：8张华为NPU

- **算力**: 8 × Huawei Ascend 910B4（每张65GB HBM）
- **数据**: 424个哈尔滨区域的遥感patch，约12,000个月度样本
- **框架**: PyTorch + 华为自研HCCL分布式后端

## 二、核心指标通俗解释

在汇报实验结果前，先解释我们关注的几个核心指标。

### 2.1 重建损失（Reconstruction Loss）

**含义**: 模型输入一张图，输出一张"重建图"，两者有多像？

**直观理解**: 就像让学生"背画"一张图，重建损失越小，说明"背得越像"。

**健康范围**: < 0.1（我们目前0.047，非常好）

**注意**: 重建损失低≠embedding好。模型可以"偷懒坍缩"也能重建得很好。

---

### 2.2 Uniformity Loss（均匀性损失）

**含义**: 衡量所有embedding向量在空间中分布得有多"散"。

**直观理解**: 想象把一堆小球撒在一个盒子里——
- **uniformity = 0**: 所有球挤在一个角落（坍缩）❌
- **uniformity = -1**: 球稍微散开一点 ⚠️
- **uniformity = -4**: 球均匀铺满整个盒子 ✅

**健康范围**: -4.0 ~ -1.0（越负越好）
- > -0.5: 严重坍缩 🔴
- -1.0 ~ -2.0: 轻度分散 🟡
- -2.0 ~ -3.0: 良好分散 ✅
- < -3.0: 非常优秀 🌟

**我们当前**: -2.0（良好，但还有提升空间）

---

### 2.3 Active Dimensions（活跃维度）

**含义**: 128维向量中，有多少维的"标准差"大于阈值（0.05）。

**直观理解**: 128个维度就像128个特征检测器——
- **active = 128/128**: 所有检测器都在工作 ✅
- **active = 88/128**: 40个检测器"罢工"了 ⚠️
- **active = 0/128**: 全部罢工，彻底坍缩 🔴

**健康范围**: > 120/128

**我们当前**: 128/128（完美）

---

### 2.4 Std Mean（平均标准差）

**含义**: 128个维度各自的波动幅度取平均。

**直观理解**: 标准差越大，embedding的"表达力"越强。

**健康范围**: 0.3 ~ 1.2
- < 0.1: 坍缩 🔴
- 0.3 ~ 0.6: 正常 ✅
- > 1.0: 非常分散 🌟

**我们当前**: 0.29 ~ 0.63（正常范围）

---

### 2.5 AUC（变化检测准确率）

**含义**: 用embedding做"变化检测"任务时的准确率。

**怎么测**:
1. 取两张不同时间的遥感图，分别提取embedding
2. 计算它们embedding的"距离"
3. 时间隔得越远，距离应该越大
4. AUC衡量：随机抽一对"远时间"和一对"近时间"，远时间的距离是否更大？

**评分标准**:
- 0.5: 随机猜测（完全没区分度）🔴
- 0.6: 有点区分度，但不够
- 0.7: 及格，能用了 ✅
- 0.8: 良好
- 0.9: 优秀

**注意**: 我们当前的AUC评估用"时间间隔"作为ground truth的代理。时间间隔大≠一定变化大（比如冬天到冬天），所以AUC只是一个参考指标，不是绝对真理。

### 3.3 第二阶段：V12 AUC验证（发现大问题）

| 实验 | AUC结果 | 含义 |
|------|---------|------|
| v12_expA_baseline | **0.499** | ≈随机猜测 |
| v12_expB_inter01 | **0.516** | 略好，但仍≈随机 |

**重大发现**: 训练loss看起来很好（recon低、uniformity好），但实际做变化检测时**完全没有区分度**！

**根因**: 模型把时序信息编码到了**embedding的"长度"（模长）**里——比如夏天的embedding向量"很长"，冬天的"很短"。但我们在推理时做了L2归一化（把向量长度统一变成1），于是时序信号被**彻底抹掉**了。

**类比**: 就像一个人用"声音大小"来区分不同乐器，但你把音量统一调成了50%，于是所有乐器听起来都一样了。

---

### 3.4 第三阶段：V13 Round1 反坍缩攻坚战（惨烈失败）

我们设计了5种反坍缩策略，同时跑10epoch：

| 实验 | 策略 | 结果 |
|------|------|------|
| Exp1 Spatial Uniformity | 在空间图上算uniformity | 10epoch → active=0 |
| Exp2 High Weight | uniformity权重×10 | 同上 |
| Exp3 VICReg Fix | 修正VICReg参数 | 同上 |
| Exp4 Combined | 三种策略全上 | 同上 |
| Exp5 Pre-norm Raw | 在pre-norm空间算uniformity | 启动后被停止 |

**结果**: 😭 **全部在10epoch内坍缩到0维！**

**根本原因**: `reconstruction_weight=0.5` + `consistency_weight=0.2` = 0.7的巨大权重，模型发现"坍缩embedding"反而能更好重建（recon从0.36降到0.10）。uniformity loss的梯度根本打不过重建损失。

3. **L2-space VICReg确实有害**（Exp4坍缩到88维）
4. **但AUC仍然低（0.53-0.64）** — 10epoch远远不够

**解释**: L2-space VICReg破坏了L2-norm空间，但**迫使模型在pre-norm空间编码更强的时序信号**作为补偿。

## 五、指标计算方式详解

### 5.1 Uniformity Loss 怎么算？

```python
# 1. 标准化: 零均值 + 单位方差
z = embeddings - embeddings.mean(dim=0)
z = z / (z.std() + 1e-4)

# 2. 计算所有两两pair的平方欧氏距离
# N个样本 → N×(N-1)/2 个pair
sq_pdist = torch.cdist(z, z, p=2).pow(2)

# 3. 计算 RBF 相似度并取对数平均
# 越分散 → 距离越大 → exp(-距离)越小 → loss越负
t = 2.0 / D  # D=128维
loss = log(mean(exp(-t * sq_pdist)))
```

**通俗版**: 把N个embedding看作N个小球，计算所有两两之间的距离。如果小球挤在一起（坍缩），距离小，loss接近0；如果小球均匀分散，距离大，loss接近-4。

### 5.2 Active Dimensions 怎么算？

```python
# 对128个维度，分别计算标准差
std_per_dim = embedding.std(dim=0)  # [128]

# 标准差 > 0.05 的维度数
active = (std_per_dim > 0.05).sum()
```

**通俗版**: 128个"特征检测器"中，有多少个还在"动弹"。如果某个维度所有样本的值都一样（std≈0），说明这个检测器"死掉了"。

### 5.3 AUC 怎么算？

```python
# 1. 随机抽200个样本，提取embedding
# 2. 两两配对，约2万个pair
# 3. 按时间间隔分类:
#    - gap >= 6个月 → positive（应该距离大）
#    - gap < 6个月  → negative（应该距离小）
# 4. 计算每对的embedding距离
# 5. ROC-AUC = P(positive距离 > negative距离)
```

**通俗版**: 随机抓一对"隔得远"的和一对"隔得近"的，看模型是否能把"隔得远"的排得更远。AUC=0.5等于瞎猜，AUC=1.0等于全对。

**局限**: 用"时间间隔"代替"真实变化"，时间隔得远≠一定变化大。
