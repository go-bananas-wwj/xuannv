# 数据处理严重问题简要说明

## 一句话总结

**S2数据预处理后标准差为0，所有像素变成同一个常数，模型从S2学不到任何有效信息。**

---

## 问题怎么发现的

调研模型输入预处理流程时，抽样检查了一个哈尔滨S2文件（patch_000000/20230113.tif），模拟完整预处理后发现：

```
预处理后S2值范围: [-0.8494, -0.8493]
预处理后S2标准差: 0.0000  ← 完全没有任何变化
```

正常应该像标准正态分布（mean≈0, std≈1，范围[-3, +3]）。

---

## 为什么会这样

### 统计量和预处理步骤"各干各的"

```
步骤1（compute_statistics.py）:
    直接读TIFF原始值 → 算mean/std
    S2 mean=1394, std=1641

步骤2（normalize_data.py）:
    先对数据做 log(x+1)/10
    然后 z-score: (log后的值 - 原始mean) / 原始std

问题: log后的值只有 [0.75, 0.87]
      原始统计量是 [1394, 1641]
      两者差了1000倍

结果: (0.8 - 1394) / 1641 = -0.85 ← 所有值都一样
```

### 正确做法（二选一）

**方法A**（推荐，对齐AEF论文）：
```
先log(x+1)/10 → 再算统计量 → 再用log统计量做z-score
```

**方法B**：
```
先z-score（用原始统计量）→ 再log(x+1)/10
```

---

## 额外发现：不同区域数据格式不一样

| 数据源 | 哈尔滨 | 大庆 | 海淀 |
|--------|--------|------|------|
| S2值范围 | 68~5917 (uint16) | 0.15~0.91 (float32) | 0.12~0.62 (float32) |
| S1值范围 | -40~+14 dB | 9~228 (原始DN) | 20~1269 (原始DN) |

**问题**：
- 哈尔滨S2是"反射率×10000"的原始格式
- 大庆/海淀S2已经是"0-1归一化"后的格式
- 对0-1的值再做log会得到极小数
- S1也是：哈尔滨是dB，大庆/海淀是原始数字

---

## 影响有多大

- 🔴 **S2输入完全失效**：std=0，模型从S2学不到任何东西
- 🟠 **当前所有实验受影响**：V1~V14的S2预处理逻辑相同
- 🟡 **模型被迫靠S1/Landsat硬撑**：但S1在大庆/海淀也有单位问题
- 🟢 **修复后预期提升**：S2信号恢复，重建质量和embedding质量应该显著提升

---

## 怎么修

### 第一步：改统计量计算脚本

让 `compute_statistics.py` 在**log变换后**再算mean/std：

```python
# 当前（错）
data = read_tif(path)  # 直接收集原始值

# 修复后（对）
data = read_tif(path)
if source_name in {"s2", "landsat"}:
    data = np.log(data + 1) / 10  # 先log
# 再算mean/std
```

### 第二步：重新生成统计量

```bash
python scripts/preprocessing/compute_statistics.py
```

### 第三步：验证

抽样检查预处理后值是否有正常分布（std≈1，范围[-3,+3]）。

### 第四步：删缓存、重启训练

```bash
find /workspace/outputs -name "dataset_cache_*.pt" -delete
```

## 关于"重新下载数据"

- **当前数据**：已经从GEE导出（大气校正、重投影、裁剪已完成）
- **没有更原始的卫星数据**（如L1C JPEG2000）
- 大庆/海淀S2是float32(0-1)，可能是GEE导出时参数不同
