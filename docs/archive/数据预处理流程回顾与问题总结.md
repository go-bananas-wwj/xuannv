## 一、完整数据流（从原始 TIFF → 模型输入）

```
原始 TIFF 文件
    ↓
read_tif(path, image_size=128) → resize (bilinear), nan→0
    ↓
normalize_data(data, source_name, stats)
    ├─ S2/Landsat: 检测0-1范围 → ×10000 → log(x+1)/10 → z-score → ±6σ clip
    ├─ S1: clip[-30, 10] → z-score → ±6σ clip
    └─ DEM: z-score → ±6σ clip
    ↓
_load_input_frames_impl → 所有帧堆叠 + 时间戳
    ↓
_load_monthly_frames → 按月过滤
    ↓
_get_item
    ├─ 输入: 当月每源随机采样最多32帧 → source_frames [3, 32, 8, 128, 128]
    ├─ 目标: 同月随机选1帧（从输入中排除该帧）→ target_images [7, 11, 128, 128]
    ├─ 空间增强: 50% 水平翻转 + 50% 垂直翻转（输入目标同步）
    ├─ 双窗口: _sample_dual_windows → w1/w2 边界
    ├─ recon_mask: 50% 像素随机 mask (128×128)
    └─ 返回 dict（含 source_frames, target_images, masks 等）
```

## 四、仍然存在的问题

### 🔴 问题1: 大庆/海淀 S1 是 DN 值，不是 dB 值（严重）

**根因**: 不同区域 S1 数据来源不同
- 哈尔滨: Google Earth Engine 导出，单位为 dB
- 大庆/海淀: 其他来源，单位为 DN (0-255 或 0-65535)

**当前代码**:
```python
if source_name in SAR_SOURCES:
    lo, hi = SAR_CLIP_RANGE  # (-30.0, 10.0)
    data = np.clip(data, lo, hi)
```

**后果**:
- 大庆 S1: DN 10~239 → clip 到 [-30, 10] → **所有值变成 10**
- 海淀 S1: DN 11~1139 → clip 到 [-30, 10] → **所有值变成 10**
- z-score 后 std≈0，**信号完全丢失**

**修复方案**:
在 `normalize_data` 中检测 S1 的值域：
```python
if source_name in SAR_SOURCES:
    if data.max() > 100:
        # DN值，需要先转换为dB
        # DN → dB 转换公式因数据源而异，常见的是: dB = 20*log10(DN) - 83.0 (Sentinel-1)
        # 或者简单线性映射到合理dB范围
        data = np.log10(np.clip(data, 1, None)) * 20 - 83.0
    data = np.clip(data, -30.0, 10.0)
```

**但问题在于**: 我们不知道大庆/海淀S1的确切DN→dB转换公式。需要查证数据源。

**临时方案**: 如果无法确认转换公式，可以像S2一样做per-sample min-max归一化，或者干脆在大庆/海淀数据中跳过S1输入（只用S2和Landsat）。

### 🔴 问题2: `compute_stats_multi_region.py` 统计量计算未修复

**文件**: `scripts/preprocessing/compute_stats_multi_region.py`

当前代码直接在原始值上计算统计量，**没有做 log 变换**：
```python
data = read_tif(tif_files[0], image_size=-1)
# 缺少: data = np.log(np.clip(data, 0, None) + 1) / 10.0
all_samples.append(data)
```

**后果**: 如果重新生成大庆/海淀统计量，会与 `normalize_data` 不匹配。

**但当前状态**: V14 配置都指向 `/workspace/statistics/harbin_scenes`，没有单独的大庆/海淀统计量，所以**当前不影响训练**。

### 🟡 问题3: recon_mask 尺寸正确但注释未更新

**文件**: `src/data/dataset.py` 第891-908行

`recon_mask` 现在生成的是 `self.image_size × self.image_size` (128×128)，注释写的是 `[target_res, target_res]`，实际 target_res 已等于 image_size。

**影响**: 无实际影响，只是注释与变量名略有不一致。

### 🟡 问题4: 目标帧排除的退化情况

**文件**: `src/data/dataset.py` 第1065-1067行

```python
if len(valid_indices) > 1:
    source_mask[s_idx, random_idx] = False
    source_frames[s_idx, random_idx] = 0.0
```

当某源当月只有 1 帧时，`len(valid_indices) == 1`，条件不成立，**目标帧不会被排除**。

**影响**: 退化回"目标在输入中"的情况。但这种情况较少（通常每源每月有多帧）。

### 🟡 问题5: 空间增强（翻转）对变化检测的影响

训练时 50% 概率水平/垂直翻转输入和目标。

**潜在问题**:
- 翻转后的变化检测标注可能不一致
- 例如: 某条道路在左半边被新建，翻转后道路在右半边，但标注 shapefile 没有翻转

**影响**: 只在训练时发生，验证时不翻转。可能让模型学到"变化与方向无关"的鲁棒性，但也可能引入噪声。

1. **哈尔滨数据**: 经过修复后，S2/S1/Landsat 预处理基本正确，统计量匹配
