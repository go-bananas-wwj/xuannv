# xuannv_embdding 项目工作总结

> **文档日期**: 2026-04-13
> **项目**: AlphaEarth Foundations 哈尔滨新区变化监测 — 改进版
> **目标**: 让模型学会对时间敏感，能做变化检测

---

## 一、项目背景

### 1.1 原始问题

原版 AEF 模型（V1）虽然重建质量好、嵌入不坍缩，但**对时间完全不敏感**：
- 用 2023 年和 2025 年的不同时间窗口查询，产生的 embedding **完全相同**
- cosine similarity = 0.97（几乎完全一样）
- 变化检测 AUC = 0.498（和随机猜测 0.5 一样）

**原因分析**：模型学到的最优策略是生成一个"时间不变的平均 embedding"，对所有时间窗口都适用，这样重建损失最小。

### 1.2 核心挑战

AlphaEarth 论文原版能做变化检测，但我们为什么不行？

| 因素 | 论文 | 我们 |
|------|------|------|
| 训练数据量 | 840 万序列 × 30 亿帧 | 424 patches × ~300 帧 |
| 时间多样性 | 全球所有气候带 | 哈尔滨一个城市 |
| 变化目标 | 11 类（含气候/重力等真正随时间变化的数据） | 7 类（主要是静态数据） |
| 模型容量 | 480M 参数 | 57M 参数 |

**关键差异**：论文模型在海量数据中"自然"学到了时间编码，而我们的数据量太小，模型选择"忽略时间"。

### 2.4 添加时序对比损失 — V2 训练

**核心思路**：在训练时对同一个 patch 用两个不同时间窗口分别编码，强制它们产生不同的 embedding。

#### 第一步：添加双窗口采样

修改数据集，每个样本输出两套 valid_start/valid_end：
- `valid_start_w1/valid_end_w1`: 前半时间窗口
- `valid_start_w2/valid_end_w2`: 后半时间窗口

#### 第二步：添加双前向编码

在模型中新增 `encode_dual_window()` 方法，对同一 batch 用两个不同 valid_period 分别做前向传播，返回两个 embedding map。

#### 第三步：添加时序对比损失

在损失函数中添加：
```python
L_temporal = cos_sim(emb_w1, emb_w2) / temperature
```

**设计意图**：
- 当 cos_sim → 1.0 (完全相同): L = 10.0 (最大值, 优化器避免)
- 当 cos_sim → -1.0 (完全相反): L = -10.0 (最小值, 优化器追求)
- 优化器会**主动把不同时间窗口的 embedding 推开**

#### 第四步：发现并修复严重 Bug ⚠️

**问题**：V2 训练了 25 个 epochs 后，Temporal Loss 卡在 -9.92 不动。

**分析**：
```
原始代码: L = -cos_sim.mean() / temperature

当 cos_sim → 1.0: L = -10.0 (最小值!) ← 优化器想要这个
当 cos_sim → -1.0: L = +10.0 (最大值!) ← 优化器避免这个
```

**❌ 效果完全相反！优化器在鼓励相同 embedding，而不是不同 embedding！**

**修复**：
```python
# 错误: L = -cos_sim.mean() / temperature
# 正确:
L = cos_sim.mean() / temperature

# 现在:
# 当 cos_sim → 1.0: L = 10.0 (优化器避免)
# 当 cos_sim → -1.0: L = -10.0 (优化器追求) ✅
```

#### 第五步：修复后重新训练

- 从 V1 checkpoint (epoch_399.pt) 重新开始
- 配置：lr=1e-5, temporal_weight=0.5, epochs=500 (400+100微调)

## 四、遇到了什么问题，怎么解决的

### 问题 1: 嵌入可视化看起来不对

**现象**：全域 PCA 拼接图颜色断裂，patch 之间不连续。

**原因**：每个 patch 用了局部归一化（2%/98% 百分位），没有全局参考。

**解决**：改用全局 PCA + 全局 1%/99% 百分位归一化，3× 最近邻上采样。参照原版 `app_v2.py` 的实现方式。

### 问题 2: 变化检测图全是均匀颜色

**现象**：全域变化强度图看起来像纯色，没有有意义的空间结构。

**原因**：
1. V1 的 Before/After embedding cosine distance = 0.03（几乎为 0）
2. 差异太小，在可视化中完全看不出来

**结论**：不是可视化的问题，是模型本身对时间不敏感。

### 问题 3: 时序对比损失符号反了（最严重的 Bug）

**现象**：V2 训练 25 epochs 后 Temporal 卡在 -9.92 不动。

**诊断过程**：
1. 检查日志 → Temporal = -9.92, 但 cos_sim 仍然 ≈ 0.99
2. 数学推导 → L = -cos_sim/0.1 → 优化器在最小化 -cos_sim → 最大化 cos_sim
3. **损失的方向完全反了！**

**修复**：去掉负号，`L = cos_sim / temperature`。

**经验教训**：添加新的损失函数时，必须先做单元测试，验证：
- 相同 embedding → loss 最大（优化器避免）
- 不同 embedding → loss 最小（优化器追求）
- 随机 embedding → loss ≈ 0

### 问题 4: 训练进程总是意外退出

**现象**：`nohup` 启动的训练经常无故退出。

**原因**：shell 会话断开时 nohup 不能保证持久性。

**解决**：用 `tmux` 会话管理训练，关闭终端也不会中断。
