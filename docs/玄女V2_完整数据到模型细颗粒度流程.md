# 玄女V2 — 从原始数据到模型输入的完整细颗粒度流程

> 本文档描述玄女（xuannv）项目中，从原始卫星影像数据到模型输入/输出的完整数据流与模型架构设计。聚焦于"数据怎么来、怎么处理、怎么进模型、模型每一层在做什么"，不涉及训练策略与实验细节。

---

## 一、项目目标

**玄女（xuannv）** 是 AlphaEarth Foundations (AEF) 的独立改进版，核心目标是训练一个能够从多时相、多源卫星影像中提取**紧凑且信息丰富**的 embedding（嵌入向量）的模型。这个 embedding 需要具备两个关键性质：

1. **时间敏感性（Temporal Sensitivity）**：能够区分不同时间窗口的地表状态，从而支持变化检测（change detection）等下游任务。
2. **反坍缩（Anti-Collapse）**：embedding 空间的各维度都被有效利用，避免模型将信息压缩到极少数维度上。

模型采用**自监督学习**范式：输入是多源时序卫星影像，输出是对这些影像的重建；通过重建任务迫使模型在 embedding 中保留足够的地理-光谱-时间信息。同时，模型需要能够根据时间条件生成特定时间点的重建结果——这意味着 embedding 必须编码了时间的动态信息，而非仅仅是静态快照。

## 二、数据：从原始成像到模型输入

### 2.1 原始数据来源

当前使用的数据覆盖**哈尔滨区域**，共约 425 个地理 patches（每个 patch 约 1km × 1km）。

数据按源分类存储为 GeoTIFF 文件，目录结构如下：

```
/workspace/raw/phase1_harbin/harbin_scenes_cloud_filtered/
├── s2/                    ← Sentinel-2（光学，云筛选后）
│   ├── patch_000000/
│   │   ├── 20230113.tif   ← 文件名 = YYYYMMDD
│   │   ├── 20230130.tif
│   │   └── ... (约22张/patch)
│   ├── patch_000001/
│   └── ...
├── s1/                    ← Sentinel-1（SAR，dB值）
├── landsat/               ← Landsat（光学）
├── dem/                   ← 数字高程模型（静态）
├── worldcover/            ← ESA WorldCover 地物分类（静态）
├── dynamic_world/         ← Dynamic World 地物分类（动态）
└── jrc_water/             ← JRC 全球水体（静态）
```

| 源 | 数据类型 | 值域 | 通道数 | 文件名格式 |
|----|---------|------|--------|-----------|
| S2 | uint16 | 0~10000+ | 6 | `YYYYMMDD.tif` |
| S1 | float32 | -38~+17 dB | 2 | `YYYYMMDD.tif` |
| Landsat | uint16 | 0~10000+ | 6 | `YYYYMMDD.tif` |
| DEM | float32 | 高程 | 1 | 单张 `.tif` |
| WorldCover | uint8 | 类别索引 | 1 | 单张 `.tif` |
| Dynamic World | uint8 | 类别索引 | 1 | 多张 `.tif` |
| JRC Water | int8 | -128=no-data | 1 | 单张 `.tif` |

**关键设计决策（对齐 AEF 论文）**：
- **仅 3 类带时间戳的图像作为输入**：S2、S1、Landsat
- **静态数据仅作重建目标**：DEM、WorldCover、Dynamic World、JRC Water 不参与编码器的输入，只在解码阶段作为重建目标。这确保模型不能直接从输入中"看到"这些静态信息，必须将它们编码到 embedding 中。

### 2.2 从 GEE 下载到 Patch 组织（原始数据生产流程）

上述 GeoTIFF 数据不是从第三方数据集直接获取的，而是通过 **Google Earth Engine (GEE)** 按需下载、按统一网格切分而成的。完整流程如下：

#### 2.2.1 定义 ROI 与 Patch 网格划分

1. **确定城市感兴趣区域（ROI）**：以哈尔滨为例，定义经纬度 bbox（如 `[125.8, 45.6, 127.2, 46.3]`）。

2. **UTM 投影转换**：根据 ROI 中心点经纬度计算 UTM 带号（哈尔滨位于 UTM Zone 52N → **EPSG:32652**），将 bbox 从 WGS84 转到 UTM 坐标系。

3. **等间距网格切分**：
   - Patch 尺寸：**1280m × 1280m**
   - 空间分辨率：**10m**（Sentinel-2 原生分辨率）
   - 每个 patch 像素数：**128 × 128**
   - 切分方式：在 UTM 坐标系下，从 bbox 左下角开始，以 1280m 为步长向右/向上遍历，生成规则网格

4. **生成元数据**：
   - `patches_meta.json`：每个 patch 的 `id`（从 0 递增）、`utm_bounds`（左/下/右/上，单位米）、`center_lonlat`（中心点经纬度）
   - `harbin_grid.geojson`：同一份网格的 GeoJSON 格式，用于后续地理空间分析（如与 shapefile 标注叠加）

哈尔滨共生成 **424 个 patches**。

#### 2.2.2 GEE 数据下载

使用 GEE Python API（`earthengine-api`）通过 Service Account 认证后批量下载。每个 patch 以**中心点 + 640m buffer** 定义下载区域，确保覆盖完整的 1280m × 1280m 范围。

| 数据源 | GEE 产品 ID | 波段 | 原始分辨率 | 下载分辨率 | 值域处理 |
|--------|------------|------|-----------|-----------|---------|
| S2 | `COPERNICUS/S2_SR_HARMONIZED` | B2,B3,B4,B5,B6,B7 | 10m | 10m | 原始 uint16（反射率×10000） |
| S1 | `COPERNICUS/S1_GRD` | VV, VH | 10m | 10m | `log10(x)*10` 转 dB，float32 |
| Landsat 8/9 | `LANDSAT/LC08/C02/T1_L2` + `LC09/C02/T1_L2` | SR_B2~B7 | 30m | 30m → 10m（GEE 重采样）| `×0.0000275 - 0.2` 转反射率 |
| DEM | `USGS/SRTMGL1_003` | elevation | 30m | 30m → 10m | float32 原始高程 |
| WorldCover | `ESA/WorldCover/v200` | Map | 10m | 10m | uint8 类别索引 |
| Dynamic World | `GOOGLE/DYNAMICWORLD/V1` | label | 10m | 10m | uint8 类别索引 |
| JRC Water | `JRC/GSW1_4/MonthlyHistory` | water | 30m | 30m → 10m | int8（-128=no-data）|

**时间范围**：`2023-01-01` 至 `2025-10-31`（约 34 个月）

**S2 云量过滤**：下载时先通过 GEE 的 `CLOUDY_PIXEL_PERCENTAGE < 20%` 预过滤，减少无效数据量。

**下载输出**：
- 每个 patch 一个子目录：`{source}/patch_{id:06d}/`
- 每帧一个 GeoTIFF 文件，文件名 = 成像日期 `YYYYMMDD.tif`
- 所有数据统一 CRS = **EPSG:32652**

#### 2.2.3 目录组织与数据量级

下载完成后，原始数据按如下结构组织（以哈尔滨为例）：

```
/workspace/raw/phase1_harbin/
├── harbin_scenes/              ← 原始下载数据（未筛选）
│   ├── s2/                     ← 约 70 帧/patch
│   ├── s1/                     ← 约 43 帧/patch
│   ├── landsat/                ← 约 48 帧/patch
│   ├── dem/                    ← 1 帧/patch（静态）
│   ├── worldcover/             ← 1 帧/patch（静态）
│   ├── dynamic_world/          ← 多张（动态）
│   └── jrc_water/              ← 1 帧/patch（静态）
└── harbin_scenes_cloud_filtered/  ← S2 云筛选后（当前训练使用）
    ├── s2/                     ← 约 22 帧/patch

    ├── landsat/ → ../harbin_scenes/landsat
```

**总数据量**：原始数据约 60-80GB，云筛选后 S2 减少到约 20GB。

### 2.3 预处理流水线

#### 2.3.1 S2 云筛选

Sentinel-2 原始数据存在大量 cloudy 帧。对每个 patch 的 S2 帧：
1. 计算 `cloud_score = brightness/10000 - NDVI`
2. 按自然月分组
3. 每月保留 cloud_score 最低的 **2 帧**
4. 若该月全部 cloudy，fallback 保留 **1 帧**

结果：原始 ~70 帧/patch → 筛选后 ~22 帧/patch。

#### 2.3.2 统计量计算

对每个源的所有帧计算 mean/std，用于后续 z-score 归一化。**关键顺序**：
- S2/Landsat：先 `log(x+1)/10` 变换，**再** 计算统计量
- S1：先 `clip[-30, 10]` dB 裁剪，**再** 计算统计量

统计量输出到 `/workspace/statistics/harbin/{source}_stats.json`。

> 这个顺序至关重要：如果统计量在 log 变换前计算，z-score 后 std 会接近 0，信号全失。

#### 2.3.3 归一化流水线（`normalize_data`）

**S2 / Landsat（光学源）**：
```
原始 TIFF → read_tif (bilinear resize 到 128×128)
    ↓
0-1 范围检测：若 max < 2.0，则 ×10000 还原
    ↓
log(clip(data, 0, None) + 1) / 10.0
    ↓
z-score: (data[c] - mean[c]) / std[c]
    ↓
clip(data, -6.0, 6.0)
```

**S1（SAR源）**：
```
原始 TIFF → read_tif (bilinear resize 到 128×128)
    ↓
clip(data, -30.0, 10.0)
    ↓
z-score: (data[c] - mean[c]) / std[c]
    ↓
clip(data, -6.0, 6.0)
```

**分类源（WorldCover / Dynamic World）**：
- class index → one-hot 编码（11 类 / 9 类）
- 不做 z-score

#### 2.3.4 内存预加载

为避免每个 epoch 重复从磁盘读取 GeoTIFF，数据集初始化时将所有 patch 的所有源预加载到内存：
1. 使用 `ProcessPoolExecutor(16 workers)` 并行加载
2. 缓存到 `/workspace/outputs/.cache_shared/dataset_cache_{hash}.pt`
3. DDP 环境下 rank 0 负责加载并保存缓存，其他 rank 等待并读取

## 三、数据采样策略

### 3.1 月度样本索引

训练样本以**自然月**为粒度组织。`__init__` 阶段构建 `monthly_samples` 列表：

```python
monthly_samples = [
    ("patch_000000", 2025, 4),
    ("patch_000000", 2025, 5),
    ("patch_000001", 2025, 4),
    ...
]
```

每个 patch 只要有任意输入源在该月有数据，就生成一个样本。当前仅使用 2025 年数据。

### 3.2 `__getitem__` 详细流程

每个样本 = `(patch_id, year, month)`，返回一个 dict。

#### Step 1: 加载输入帧

对 3 个输入源（S2、S1、Landsat），分别加载该 patch 该月的所有帧：

```python
for s_idx, src_name in enumerate(["s2", "s1", "landsat"]):
    frames, ts = _load_monthly_frames(patch_id, src_name, 2025, month)
```

`_load_monthly_frames` 内部：
1. 从预加载缓存或磁盘读取该 patch 该源的所有帧
2. 过滤时间戳在 `[month-01, month-last_day]` 范围内的帧

**实际帧数**（云筛选后月度采样）：
- S2：每月 1-2 帧（冬季 fallback 时可能仅 1 帧）
- S1：每月 2-4 帧
- Landsat：每月 1-4 帧

`max_frames=32` 在云筛选后的月度采样模式下**基本不会触发**，该参数主要是为兼容性预留（如未来使用未筛选数据、或扩大时间窗口范围时可能生效）。实际场景中，每月各源通常只有 2-4 帧，`source_mask` 只有前 2-4 个位置为 True。

**示例**：某 patch 的 S2 在 2025-05 有 2 帧，S1 有 3 帧，Landsat 有 2 帧：
- `source_frames` shape: `[3, 32, 6, 128, 128]`
- `source_mask`: 只有前 2/3/2 个位置为 True，其余为 False
- `source_input_mask`: `[True, True, True]`

#### Step 2: 构建目标帧

**目标源**：S2(6ch)、S1(2ch)、Landsat(6ch)、DEM(1ch)

**动态目标（S2/S1/Landsat）**：
- **同月重建**（默认）：从输入帧中 `random.choice` 1 帧作为目标
- **关键设计**：将该帧从 `source_mask` 中设为 False，`source_frames` 对应位置置 0
  - 目的：避免模型直接复制输入帧完成重建（退化为恒等映射）
  - 退化保护：当月只有 1 帧时不排除
- **跨月重建**（可选）：从其他月份加载目标帧，decoder 需根据时间条件生成该月份的重建

**静态目标（DEM）**：
- 从缓存/磁盘读取单张 TIFF
- 读取原始尺寸 → z-score → bilinear resize 到 128×128
- `target_relative_time = 0.5`（静态时间偏移）

#### Step 3: 空间增强（训练时）

```python
if random.random() < 0.5:
    source_frames = source_frames[..., ::-1, :].copy()   # 水平翻转
    target_images = target_images[..., ::-1, :].copy()
if random.random() < 0.5:
    source_frames = source_frames[..., ::-1].copy()       # 垂直翻转
    target_images = target_images[..., ::-1].copy()
```

输入和目标同步翻转，确保地理对齐性。

#### Step 4: 双时间窗口采样

对当月所有时间戳排序，采样两个时间窗口：

```
w1 = [ts[0], ts[mid-1]], w2 = [ts[mid], ts[-1]]
```

支持多种模式：
- `random_split`：中点分割（默认）
- `adjacent_month`：相邻两个月
- `mixed_scale`：长间隔(≥6月)或短间隔(1-3月)
- `non_overlap`：非重叠长间隔

#### Step 5: 返回 batch dict

```python
{
    "source_frames":         [3, 32, 6, 128, 128]   float32
    "source_timestamps_ms":  [3, 32]                float64
    "source_frame_mask":     [3, 32]                bool
    "source_input_mask":     [3]                    bool
    "source_type_ids":       [3]                    int64 (0=S2, 1=S1, 2=Landsat)
    "valid_start_ms":        scalar                 float64
    "valid_end_ms":          scalar                 float64
    "valid_start_w1/w2":     scalar                 float64 (双窗口边界)
    "valid_end_w1/w2":       scalar                 float64
    "target_images":         [4, 11, 128, 128]      float32 (4个目标源)
    "target_relative_time":  [4]                    float32
    "target_metadata":       [4, 4]                 float32
    "target_mask":           [4]                    bool
    "target_loss_type":      [4]                    int64 (0=连续/L1)
    "target_source_idx":     [4]                    int64
}
```

## 四、模型架构：从输入到输出

### 4.1 整体架构概览

```
Input: [B, S=3, T=32, C=6, H=128, W=128]
    ↓
SensorEncoderBank        → [B, S, T, 128, 64, 64]
    ↓
Flatten (S×T)            → [B, 96, 128, 64, 64]
    ↓
STPEncoder (8 blocks)    → [B, 96, 128, 64, 64]
    ↓
时间条件摘要 (attention)  → [B, 128, 64, 64] (summary_map)
    ↓
VMFBottleneck            → [B, 64, 64, 64] (embedding_map)
    ↓
Decoder (逐像素 MLP)      → [B, out_ch, 64, 64]
    ↓
F.interpolate            → [B, out_ch, 128, 128]
    ↓
Output reconstructions
```

**关键维度**：
- `space_dim = 768`, `time_dim = 384`, `precision_dim = 128`
- `num_blocks = 8`
- `embedding_dim = 64`
- 总参数量：**3.58 亿**（STPEncoder 占 3.57 亿）

> 对比论文原始配置：space_dim=1024, time_dim=512, 15 blocks → 约 9.93 亿。当前已缩小到 space=768, time=384, 8 blocks → 3.58 亿，以适配 NPU 显存。

### 4.2 传感器编码器（SensorEncoderBank）

**设计原则**：不同传感器（S2/S1/Landsat）的光谱特性差异极大，必须使用独立的 stem 编码器。

**每个源的编码器**：
```
Input: [B*T, C_in, 128, 128]
    ↓
adapter (可选 1×1 Conv)   → [B*T, C_stem, 128, 128]
    ↓
stem: Conv3×3(stride=2)   → [B*T, stem_dim=128, 64, 64]
      + BatchNorm + GELU
    ↓
projection: Conv1×1       → [B*T, out_dim=128, 64, 64]
      + BatchNorm + GELU
    ↓
Output: [B*T, 128, 64, 64]
```

**Bank 组装**：
```python
for s_idx in range(S):
    frames = source_frames[:, s_idx, :, :, :, :]   # [B, T, 6, 128, 128]
    frames = frames.reshape(B * T, 6, 128, 128)    # [B*T, 6, 128, 128]
    enc = encoder(frames)                           # [B*T, 128, 64, 64]
    enc = enc.reshape(B, T, 128, 64, 64)            # [B, T, 128, 64, 64]
```

输出 `encoded` shape `[B, S=3, T=32, 128, 64, 64]`

### 4.3 Flatten 到统一序列

```python
frames = encoded.reshape(B, S * T, 128, 64, 64)     # [B, 96, 128, 64, 64]
timestamps = source_timestamps_ms.reshape(B, S * T)  # [B, 96]
mask = (effective_frame_mask & source_input_mask).reshape(B, S * T)  # [B, 96]
```

**关键设计**：多源帧展平为单一时间序列。TimeOperator 在 96 个"时间步"上做 attention，不同源通过 `timestamps_ms` 的正弦编码区分。这是 AEF 论文的原始设计——模型不区分数据来源，只关心"什么时候拍的照片"。

### 4.4 STP Encoder（核心）

STP = Space-Time-Precision。这是模型的核心创新，也是参数量最大的部分。

#### 4.4.1 初始投影到三条路径

```python
# Space path: 128 → 768, 下采样到 1/16L (8×8)
space = Conv1x1(128→768)(x_flat)                     # [B*96, 768, 64, 64]
space = F.adaptive_avg_pool2d(space, (8, 8))         # [B*96, 768, 8, 8]
space = space.reshape(B, 96, 768, 8, 8)              # [B, 96, 768, 8, 8]

# Time path: 128 → 384, 下采样到 1/8L (16×16)
time = Conv1x1(128→384)(x_flat)                      # [B*96, 384, 64, 64]
time = F.adaptive_avg_pool2d(time, (16, 16))         # [B*96, 384, 16, 16]
time = time.reshape(B, 96, 384, 16, 16)              # [B, 96, 384, 16, 16]

# Precision path: 保持 1/2L (64×64)
precision = x_flat.reshape(B, 96, 128, 64, 64)       # [B, 96, 128, 64, 64]
```

**为什么分三条路径？**
- **Space path**：在高语义维度（768-dim）、低空间分辨率（8×8）上做 ViT-style 空间自注意力。适合捕捉"这块地是什么"的全局语义。
- **Time path**：在中等维度（384-dim）、中等分辨率（16×16）上做时间轴自注意力。适合捕捉"这块地随时间怎么变"的动态模式。
- **Precision path**：在低维度（128-dim）、高空间分辨率（64×64）上做 3×3 卷积。适合保留精细的空间纹理和边界信息。

三条路径分别负责不同粒度的信息，最后融合，实现多尺度表示。

#### 4.4.2 单个 STPBlock（循环 8 次）

```
Input:
  space:    [B, 96, 768, 8, 8]
  time:     [B, 96, 384, 16, 16]
  precision:[B, 96, 128, 64, 64]
    ↓
┌─────────────────────────────────────────────────────┐
│ 各路径独立计算                                       │
├─────────────────────────────────────────────────────┤
│ SpaceOperator:                                       │
│   reshape: [B, 96, 768, 8, 8] → [B*96, 64, 768]     │
│     (8×8=64 个空间位置，每个位置 768-dim)             │
│   LayerNorm + QKV(768→2304) + MHA(8 heads) + MLP    │
│   reshape 回来 → [B, 96, 768, 8, 8]                 │
├─────────────────────────────────────────────────────┤
│ TimeOperator:                                        │
│   + sinusoidal time encoding (timestamps_ms)         │
│   reshape: [B, 96, 384, 16, 16] → [B*256, 96, 384]  │
│     (16×16=256 个空间位置，每个位置过 96 个时间步)     │
│   LayerNorm + QKV(384→1152) + MHA(8 heads) + MLP    │
│   frame_mask 屏蔽无效帧（softmax 前 -inf）            │
│   reshape 回来 → [B, 96, 384, 16, 16]               │
├─────────────────────────────────────────────────────┤
│ PrecisionOperator:                                   │
│   reshape: [B, 96, 128, 64, 64] → [B*96, 128, 64, 64]│
│   GroupNorm + Conv3×3(128→512) + GELU               │
│   GroupNorm + Conv3×3(512→128) + 残差               │
│   reshape 回来 → [B, 96, 128, 64, 64]               │
└─────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────┐
│ 6 方向跨尺度交换 (LearnedSpatialResampling)          │
├─────────────────────────────────────────────────────┤
│ Space ← Time:    ConvTranspose2d(384→768, k=4, s=2) │
│   上采样 2×: 16×16 → 8×8                            │
│ Space ← Precision: Conv2d(128→768, k=15, s=8, p=7)  │
│   下采样 8×: 64×64 → 8×8                            │
│ Time ← Space:    Conv2d(768→384, k=3, s=2, p=1)     │
│   下采样 2×: 8×8 → 16×16                            │
│ Time ← Precision: Conv2d(128→384, k=7, s=4, p=3)    │
│   下采样 4×: 64×64 → 16×16                          │
│ Precision ← Space: ConvTranspose2d(768→128, k=4,s=2)│
│   上采样 2× + bilinear 补 4×: 8×8 → 64×64           │
│ Precision ← Time: ConvTranspose2d(384→128, k=4,s=2) │
│   上采样 2× + bilinear 补 2×: 16×16 → 64×64         │
├─────────────────────────────────────────────────────┤
│ 融合：各路径接收其他两路信息后直接相加                │
│   space_out = space_2d + time_to_space + precision_to_space │
│   time_out  = time_2d + space_to_time + precision_to_time   │
│   precision_out = precision_2d + space_to_precision + time_to_precision │
└─────────────────────────────────────────────────────┘
```

**为什么需要跨尺度交换？**
- 如果没有交换，三条路径完全独立，Space path 永远看不到时间信息，Time path 永远看不到精细空间信息。
- 6 方向交换确保：**每个 block 后，每条路径都融入了其他两条路径在当前尺度下的信息**。
- 使用 `LearnedSpatialResampling`（可学习的 Conv/ConvTranspose）而非简单的 bilinear resize，让网络自己学习如何跨尺度传递信息。

#### 4.4.3 最终融合

```python
# Space 上采样回 64×64
space_up = ConvTranspose2d(768→128, k=4, s=2)(space_flat)   # [B*96, 128, 16, 16]
space_up = F.interpolate(space_up, (64, 64))                  # [B*96, 128, 64, 64]

# Time 上采样回 64×64
time_up = ConvTranspose2d(384→128, k=4, s=2)(time_flat)      # [B*96, 128, 32, 32]
time_up = F.interpolate(time_up, (64, 64))                   # [B*96, 128, 64, 64]

# 三条路径相加 + GroupNorm
out = space_up + time_up + precision_flat                     # [B*96, 128, 64, 64]
out = GroupNorm(out)
out = out.reshape(B, 96, 128, 64, 64)                        # [B, 96, 128, 64, 64]
```

### 4.5 时间条件摘要

STPEncoder 输出 96 个帧的 feature map。需要将它们压缩为一个固定的空间摘要（summary_map）。

```python
pooled = x.mean(dim=(-2, -1))           # [B, 96, 128]  每帧全局平均
query = summary_query(window_code)       # [B, 128] → [B, 1, 128]
attn_scores = sum(query * pooled, dim=-1) # [B, 96]
attn_scores = attn_scores.masked_fill(~mask, -1e9)  # 屏蔽无效帧
attn = softmax(attn_scores, dim=-1)      # [B, 96]
summary = einsum("bt,btchw->bchw", attn, x)  # [B, 128, 64, 64]

# 将逐帧时间编码融入空间摘要
time_summary = time_codes.mean(dim=1)     # [B, time_code_dim=64]
summary = summary + time_to_summary(time_summary)[:, :, None, None]  # broadcast
```

**为什么用 attention-based pooling？**
- 简单的 mean pooling 会让所有帧等权重，无法突出关键帧。
- attention 机制让模型根据 `window_code`（时间窗口编码）选择性地关注某些帧。
- `time_to_summary` 将时间编码真正融入空间摘要，替代了之前不传递信息的 dummy 操作。

### 4.6 VMF Bottleneck

```python
pre_norm_map = Conv1x1(128→64)(summary_map)    # [B, 64, 64, 64]

if self.training and self.skip_l2_training:
    # skipL2 模式: 跳过 L2 Norm，保留原始幅度
    embedding_map = pre_norm_map
    embedding_vector = embedding_map.mean(dim=(-2, -1))   # [B, 64]
else:
    # 标准模式: L2 归一化 + VMF 噪声
    embedding_map = F.normalize(pre_norm_map, p=2, dim=1)   # [B, 64, 64, 64]
    if training and kappa > 0:
        noise = randn_like(embedding_map) * sqrt(1/kappa)   # VMF 噪声
        noisy = embedding_map + noise
        embedding_map = F.normalize(noisy, p=2, dim=1)      # 重新归一化
    embedding_vector = embedding_map.mean(dim=(-2,-1))      # [B, 64]
    embedding_vector = F.normalize(embedding_vector, p=2, dim=1)

pre_norm_vector = pre_norm_map.mean(dim=(-2,-1))        # [B, 64]
```

**为什么用 VMF（Von Mises-Fisher）分布？**
- embedding 被约束在单位超球面上（L2 Norm = 1）。
- 球面上的距离用 cosine similarity（即角度距离），比欧氏距离更适合高维 embedding 的比较。
- VMF 噪声在球面上采样，模拟观测不确定性，增强鲁棒性。
- `skip_l2_training` 提供了一个对照路径：跳过 L2 归一化，在原始幅度空间计算损失，避免 L2 的 Jacobian 梯度屏障。

**Difference Module（双窗口时使用）**：
```python
# 对两个窗口的 summary_map 分别 embedding
pre_w1 = to_embedding(summary_w1)      # [B, 64, 64, 64]
pre_w2 = to_embedding(summary_w2)

# 显式编码差分
diff_feat = diff_encoder(cat([pre_w1, pre_w2], dim=1))  # [B, 32, 64, 64]
change_score = sigmoid(change_gate(diff_feat))           # [B, 1, 64, 64]

# 融合：原始 embedding + 差分特征 → 增强版 embedding
fused_w1 = fusion(cat([pre_w1, diff_feat], dim=1))      # [B, 64, 64, 64]
fused_w2 = fusion(cat([pre_w2, diff_feat], dim=1))

emb_w1 = L2_normalize(fused_w1)
emb_w2 = L2_normalize(fused_w2)
```

这是变化检测的核心：模型显式学习"两个时间窗口的差异是什么"。

### 4.7 条件解码器

#### 4.7.1 条件注入

```python
cond = cat([window_code, relative_time, metadata], dim=-1)  # [B, 64+16+4=84]
cond_emb = proj(cond)                                        # [B, 64]
embedding = embedding + cond_emb[:, :, None, None]           # broadcast 加法
```

条件通过**加法**注入，非拼接。这保持 MLP 输入维度不变（仍为 `embedding_dim=64`），同时让 decoder 知道"要重建哪个时间点的什么源"。

#### 4.7.2 逐像素 MLP（对齐 AEF 论文 S2.4）

论文原文："Implicit decoders were two-hidden-layer MLPs with a width of 512."

```python
Input: [B, 64, 64, 64]
    ↓
permute + reshape: [B*64*64, 64]
    ↓
Linear(64 → 512) + GELU + LayerNorm
    ↓
Linear(512 → 512) + GELU + LayerNorm
    ↓
Linear(512 → out_ch)
    ↓
reshape + permute: [B, out_ch, 64, 64]
```

每个空间位置 `(h, w)` 的 64-dim embedding 独立过 MLP，输出 `out_ch` 个重建值。

**为什么用逐像素 MLP 而非 UNet-style 上采样？**
- AEF 论文设计：decoder 应该是"轻量"的，重建能力主要来自 encoder/bottleneck 的表示质量。
- 如果 decoder 太强大（如 UNet），模型可能学会将信息藏在 decoder 中，bottleneck 的 embedding 反而变得信息量不足。
- 逐像素 MLP 强制每个位置只依赖自己的 embedding，倒逼 bottleneck 输出足够信息量的 spatial embedding。

#### 4.7.3 上采样回到原始分辨率

```python
if dec_h != 128 or dec_w != 128:
    flat_recon = F.interpolate(flat_recon, size=(128, 128),
                                mode='bilinear', align_corners=False)
```

最终 reconstruction: `[B, T_tgt=1, max_ch=11, 128, 128]`

## 五、当前进展总结

截至目前，玄女V2 已完成以下核心模块的从零实现与数据对齐：

1. **完整数据流水线**：从原始 GeoTIFF（S2/S1/Landsat/DEM 等）到模型输入的端到端流程，包括云筛选、统计量计算、log/z-score 归一化、内存预加载。

2. **月度样本索引与采样策略**：以自然月为粒度组织训练样本，支持输入帧随机采样、目标帧从输入中排除、双时间窗口采样、跨时相重建。

3. **STP Encoder（核心创新）**：严格对齐 AEF 论文的三路径设计（Space=768-dim @ 1/16L, Time=384-dim @ 1/8L, Precision=128-dim @ 1/2L），含 6 方向跨尺度 LearnedSpatialResampling 交换，共 8 个 blocks。

4. **VMF Bottleneck**：L2 归一化 + VMF 噪声的球面 embedding，支持 skip-L2 对照路径；含显式 Difference Module 用于双窗口变化检测。

5. **条件解码器**：逐像素 2 层 MLP（hidden=512）+ 条件注入（时间/窗口/元数据），输出后 bilinear 上采样回 128×128。

6. **模型规模适配**：从论文 15 blocks/1024-dim 适配到 8 blocks/768-dim，参数量从约 9.93 亿降到 3.58 亿，以在 NPU 上稳定运行。
