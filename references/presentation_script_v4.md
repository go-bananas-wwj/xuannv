## P1 封面：玄女底座——自研地球嵌入基座

**【任总，上次您说想看看咱们这块到底做成什么样了，今天给您汇报一下。】**

今天汇报的主题是「玄女底座」。简单说，这是一个我们自己从零搭出来的地球嵌入基座，不是基于别人开源模型改的，而是完全自研。核心目标就一个：把海量的卫星遥感数据，压缩成几十个字节的向量，同时保留住时间变化和空间结构的信息。

您可以把想象成给地球拍了一套「语义照片」，每一张照片只有 64 字节，但包含了那片区域在特定时间的光谱、地形、土地利用等全部信息。这样下游的任何应用——变化检测、地物分类、目标检索——都可以直接在这个向量上做，不用回头去翻原始影像。

好，咱们一页一页来看。

## P2 模型原理：输入 → STP 编码器 → 三重损失 → 64 维输出

**【这一页是模型的骨架，我尽量说人话。】**

我们的输入是三种卫星时序数据：S2（光学）、S1（雷达）、Landsat。这些东西原始体量非常大，一张照片动辄几个 G。进入模型后，首先经过一个我们设计的 STP 编码器，S 是 Space（空间），T 是 Time（时间），P 是 Precision（精度）。三管齐下，把时空信息编码到一个高维特征空间里。

然后进入一个瓶颈层，叫 VMF Bottleneck。训练的时候我们故意跳过了 L2 归一化，直接在 pre-norm 空间算损失，这样可以防止嵌入坍缩——这个是后面我会详细说的一个坑，很多模型都会掉进去。推理的时候再正常做 L2+VMF，保证输出在球面上，方便下游做余弦相似度。

最后一脚，64 维向量，如果用 int8 量化，只有 64 字节。这张图您可以看到整个流程：输入 → 编码器 → 瓶颈 → 输出，下面还标了我们训练时用的三重损失目标：重建损失、反坍缩损失、时序对比损失。

## P3 核心亮点：三句话讲清楚我们跟别人的区别

**【任总，这一页我想用三句话，把咱们最核心的差异化讲清楚。】**

**第一，反坍缩训练。** 大多数自监督模型训练到最后，所有样本的嵌入会坍缩到同一个方向，像所有人挤在一个角落里。我们设计了一套 raw uniformity + decorrelation + variance + orthogonality 的组合拳，强制嵌入在空间里均匀散开。您后面会看到数据，我们的 uniformity 指标是负的，说明嵌入分布得很开。

**第二，时序敏感。** Google 的 AEF 用的是年度级别的数据，而我们训练时强制使用不重叠的双时间窗口，并且要求两个窗口的嵌入在余弦空间里有明显差异。这意味着我们的模型天然对时间变化敏感，可以检测月度级别的地表变化。

**第三，纯自研。** 不是基于 AEF 改的，不是基于 Clay 改的，是从数据加载、网络结构、损失函数到训练流程全部自己写的。这意味着知识产权干净，后续升级也完全自主可控。

## P4 变化检测：有 CD Head 时 BA 79.8%，高于 AEF 的 71.3%

**【这一页是硬指标，咱们直接上数字。】**

变化检测是地球嵌入最重要的下游任务之一。我们在哈尔滨 69 个有标注的 patch 上做了测试。

三个柱状，从左到右：AEF 的 unsupervised BA 是 71.3%，这是 Google DeepMind 论文里的官方数字。中间红色柱子是我们加上 CD Head 之后的 BA，79.8%。右边黄色柱子是我们纯 raw embedding 的 BA，大约 50%。

**任总，这里我想诚实地说两点：** 第一，加上 CD Head 之后我们确实超过了 AEF，而且这个提升是稳定的，AUC 到了 95.5%。第二，如果不加 CD Head，只用原始嵌入的余弦距离，我们的 BA 大概只有 50%，跟 AEF 的 71.3% 还有明显差距。这个差距我们会后面通过 V6、V6.5 逐步补上。

**【这一页把咱们跟几个主流模型做个全景对比。】**

雷达图六个维度：压缩效率、时序敏感性、无监督变化检测、多模态融合、检索工具、中国场景验证。

红色线是我们。可以看到，**我们在时序敏感性、压缩效率和中国场景验证这三个维度上是明显领先的。** 变化检测和多模态融合跟 AEF 接近，检索工具我们虽然还没做正式的 UI，但底层能力已经具备了。

## P6 V5 评估数据分布：69 个 patch 的 BA 和 AUC 分布

**【这一页给您看一下我们实际测试的分布，不是只拿一个最好数字忽悠您。】**

左边是 BA 分布直方图，横轴是 Balanced Accuracy，纵轴是 patch 数量。可以看到大部分 patch 落在 0.75~0.85 之间，均值 0.798，我用红色虚线标出来了。灰色虚线是 AEF 的 0.713，作为对比。

右边是 AUC 分布，大部分在 0.93~0.98 之间，均值 0.955。这个分布说明我们的结果不是偶然的，而是比较稳定的。

**任总，这里我想强调一下：** 这 69 个 patch 是在哈尔滨 695 平方公里范围内、由人工标注的真实变化区域，不是我们自己合成的测试集。所以这个结果是有说服力的。

## P7 轻量化检索：23TB 原始数据 → 3GB 嵌入库 → 16MB 本机嵌入

**【这一页我想给您展示一下，这个东西用起来有多轻。】**

最上面是原始卫星影像，以 MajorTOM 数据集为例，完整的数据量是 23TB。这个量级，普通服务器都存不下，更别提个人电脑了。

中间一层是 EarthEmbeddingExplorer 的做法，他们把 6 个模型的嵌入预计算出来，压缩到了大约 3GB。这已经是一个很大的进步了，3GB 可以放在普通笔记本上离线运行。

最下面一层是我们玄女底座的输出。64 维 int8 向量，一个 patch 的嵌入只有 64 字节。如果覆盖整个哈尔滨 695 平方公里，全部嵌入加起来大约 16MB。**16MB，任总，这比一张高清照片还小。** 任何设备——手机、平板、边缘计算盒子——都可以离线跑。

这里我们还有一段 EarthEmbeddingExplorer 的演示视频，您可以看到用自然语言检索卫星影像的场景。我们下一步也会做类似的检索界面，但底层会比他们更轻、更快。

## P9 诚实面对：V5 原始嵌入 BA ~50%，与 AEF 71.3% 还有差距

**【任总，这一页我想坦诚地跟您汇报一下我们的短板。】**

上一页我说了加上 CD Head 之后 BA 79.8%，超过 AEF。但如果不加 CD Head，只用 raw embedding 的余弦距离，我们的 BA 大概只有 50%。AEF 的 raw embedding 可以做到 71.3%。

这个差距的来源，我们分析主要是两个：第一，AEF 的训练数据量比我们大很多，他们用了全球级别的数据，我们目前只在哈尔滨做了密集训练。第二，AEF 的模型更深，参数量更大，表征能力自然更强。

**但这个差距不是结构性的。** 我们的训练框架已经搭好了，下一步只需要扩大数据量和升级模型结构。V6 和 V6.5 的目标就是把 raw embedding 的 BA 逐步提升到 60%、70%，最终接近甚至超过 AEF。

## P10 升级路线图：V6 → V6.5 → V7，目标 raw BA > 70%

**【这一页是我们的三步走计划。】**

V5 是当前版本，混合尺度双窗口 + CD Head，在哈尔滨 695 平方公里验证通过。这是已经做完的。

V6 是正在进行中的版本，核心升级是 pixel-level temporal loss，也就是在像素级别上做时序对比，而不是像 V5 那样只在全局 mean pooling 之后做。目标是把 raw embedding 的 BA 推到 60% 以上。

V6.5 是下一步，gap-aware temporal sensing，也就是让模型对不同时间间隔的变化有不同的敏感度。比如 1 个月的变化和 6 个月的变化，模型知道用不同的阈值去判断。目标 raw BA 70% 以上。

V7 是长期目标，引入 Temporal Transformer 和更大规模的自监督预训练，数据量扩展到全国级别，争取在通用性上接近甚至超过 AEF。
